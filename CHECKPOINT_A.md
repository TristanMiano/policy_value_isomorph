# Checkpoint A review and frozen research interfaces

Reviewed 2026-11-20, covering Tasks 23–29 through revision `f779bc3` and the two corrections below. Later experiments can use the package interfaces listed here. Keep the existing convention for whose gain receives a positive sign. The project's proposal that scores give meaning to choices is compatible with both signed game points and observed move frequencies. Each experiment still has to specify what its scores measure and how each player chooses from them.

## What the review found

**Freezing a player previously left its weights shared with the caller.** A policy is a rule for choosing a move. The neural policy scores the nine cells, takes the highest-scoring legal cell and breaks ties by lowest cell number. Starting with nine tied scores on the empty board, changing the supplied model after freezing could move the frozen player's choice from cell 0 to cell 8. The freeze operation now copies the weights once. In the regression test, the live model chooses 8 after the edit and the frozen player still chooses 0. This matters when later games supply observations of the original player. [Implementation](src/policy_value_isomorph/rollout_value.py) · [Weight-mutation test](tests/test_rollout_and_recovery.py)

**Connect Four's move selector always read scores as X's payoff.** The root player is the player whose win is worth +1, draw 0 and loss −1. The move selector now takes that player as an optional argument, retaining X as the default. In two test positions, one with X to move and one with O to move, column 3 wins immediately. Giving an unfinished board 0 points and scoring for O, the old rule chose column 0 in both positions. With the root specified, the selector chose the winning column under both viewpoints in both positions. With all columns tied, it chose column 0 in all four cases. These are targeted checks on Connect Four. [Selector](src/policy_value_isomorph/connect_four_pipeline.py) · [Positions and expected choices](tests/test_connect_four.py)

**The tic-tac-toe payoff convention held across the entire game.** A rollout plays to the end using a specified rule. For this check both players take an immediate win, block an immediate loss, take the center, take a corner, or take any legal cell, in that order, choosing the lowest cell within a priority. We compared playing each position forward with a second calculation working backward from the terminal boards. For each of X's and O's viewpoints, the maximum absolute difference was **0 game points** across all 5,478 board values and all 16,167 legal board–move values. Reversing the viewpoint and the direction of comparison changed the selected move on **0 of 4,520** boards with a legal move. These are exact counts because the rule chooses one move with certainty and every reachable board was included. They measure consistency of the payoff calculation. Agreement with the original player's own choices is a different measurement. [Exhaustive check](tests/test_pilot_exact.py) · [Independent calculation](src/policy_value_isomorph/pilot_exact.py)

## What later experiments can rely on

The names below are imported from `policy_value_isomorph` except where a submodule is given. A **board value (V)** is the expected final payoff starting at a board. A **board-and-move value (Q)** is the expected final payoff after forcing one legal move and then continuing. In tic-tac-toe that move produces a single next board, and points are awarded only at game end. Under the same continuation rule, the move's expected payoff therefore equals the resulting board's expected payoff. When selecting a move by fixed-root payoff, the root player chooses the largest value and the other player chooses the smallest. Equal payoffs resolve to the lowest legal move number.

| Operation | Public interface and meaning |
| --- | --- |
| Represent a board and a move | `TicTacToeState(board, to_move)` records nine cells in row order, numbered 0–8. X is +1, O is −1, and an empty cell is 0. `legal_moves()` lists playable cells in ascending order. `apply_move(move)` returns the next board. `terminal_return(root_player)` returns the final points. `StateActionSample(state, action)` records an observed choice. |
| Sample decisions | `generate_on_policy_dataset(policy, n_episodes)` starts each game empty and records each move with the supplied policy playing both seats. A policy that samples its moves controls its own random draws. `generate_off_policy_dataset(n_episodes, seed)` starts empty and samples each legal move with equal probability, using the seed to reproduce the draws. Both return lists of `StateActionSample` and retain repeated board visits. |
| Generate game-payoff training data | `estimate_v_pi(state, policy, root_player, n_rollouts=1)` and `estimate_q_pi(state, action, policy, *, root_player, n_rollouts=1)` average the root player's points with the supplied policy playing both seats. `generate_value_targets` and `generate_q_targets` take named `root_player` and `rollout_budgets` arguments. They return `StateValueTarget(state, n_rollouts, value)` and `StateActionValueTarget(state, action, n_rollouts, value)` respectively. Each value is the mean payoff over the specified number of games. The experiment records the root player alongside these records. |
| Choose using game payoff | `recovered_action_from_v(state, policy, root_player, n_rollouts=1)` evaluates each resulting board by rollout. To use a fitted board network, score each legal move with `value_mlp_predict(state.apply_move(move), model)` and use the same root and tie rules. `q_mlp_predict(state, action, model)` scores a move directly and `recovered_action_from_q(state, model, *, root_player)` selects it. In Connect Four use `recovered_action_from_v_connect_four(state, value_fn, *, root_player=1)`, supplying a function that scores a resulting board for that root. |
| Fit and use a neural player | A multilayer perceptron (MLP) here is a network with one intermediate layer using the hyperbolic tangent function. `train_policy_mlp`, `train_value_mlp` and `train_q_mlp` return `.model` and `.training_log` with per-pass `.losses` and `.telemetry` (training measurements). Policy and V take ten inputs, the nine cells and the player to move. Policy emits nine move scores and V emits one board score. Q adds nine indicators identifying the candidate move and emits one score. `policy_mlp_action(state, model)` selects the highest-scoring legal move. `frozen_policy_from_mlp(model)` fixes that rule and its weights at the time of the call. `policy_mlp.policy_mlp_probabilities(state, model)` returns nine probabilities, exponentiating scores and normalizing over legal moves only. |
| Configure training and continue it | `training_config.TrainingConfig` is passed as `config=`. The default uses 64-bit arithmetic on the central processor and stochastic gradient descent (SGD), which updates weights in the direction that reduces training error on each example. AdamW, an update that adapts step sizes and applies weight shrinkage separately, is selectable. The trainers accept `checkpoint_dir`, `checkpoint_interval`, `resume_latest` and `resume_checkpoint_path`. A checkpoint saves a fit for continuation. The version 2 `.pt` format preserves weights, optimizer memory, example order and random state. On resume, `epochs` is the total number of passes desired and the returned log covers the additional passes. Earlier JSON checkpoints support their original SGD continuation. |
| Read saved runs and measurements | `checkpointing.latest_checkpoint_path` chooses the highest saved step, preferring the native `.pt` file when the same step exists in both formats. `checkpointing.load_checkpoint(path, model_type=...)` restores the public model. In `telemetry.TrainingTelemetry`, each `TelemetryRecord` gives the pass number starting at 1, training error and elapsed seconds. The writers in `telemetry_io` append these records as one structured record per line or as comma-separated rows. `telemetry_run_dir` in that module locates the logs by game, network type and random seed. |
| Measure moves and game results | `action_agreement_rate` gives the fraction of supplied decision boards on which two policies choose the same move, weighting each entry equally, including repeats. `top_k_agreement_rate` gives the fraction where the reference move is among the first `k` legal moves ranked by the mover's score, highest first. `win_draw_loss_rate(player_policy, opponent_policy, n_games)` plays from the empty board, alternates seats beginning with the evaluated player as X and returns that player's three outcome fractions over all games. |

PyTorch is the library used to train the networks. The supported boundary is the public calls, data meanings and saved-run behavior above. Experiments can use those without importing the shared training loop. The installed `policy-value-cli` command provides `data`, `train`, `eval` and `plots` for preparing examples, fitting networks, evaluating players and plotting training records. [Commands and examples](REPRODUCIBILITY.md)

**Move frequency and complete-game utility carry their own meanings.** A move frequency is its observed count divided by all observed moves from that board. For direct reconstruction the mover prefers the larger fitted frequency in either seat. For von Neumann–Morgenstern (VNM) expected-utility selection, utility means the assigned numerical score of a complete play. The selector compares the mean of that same utility after each candidate move using the declared rules for both players. The visit-trained experiments orient scores to X for computing complete-play utilities, then orient them to the mover for selection. Thus positive may mean frequent for this mover in one calculation and favorable to X in another. The reconstruction experiments must retain that distinction when reporting move agreement and win, draw and loss rates. [Visit-score implementation](scripts/run_tictactoe_choice_training.py) · [Complete-play calculations](src/policy_value_isomorph/trajectory_utility.py)

## Evidence from Tasks 23–29

The saved-weight replay covers five original players. One uses the win/block/center/corner rule defined above. One takes the lowest-numbered move with the best payoff it can guarantee against best replies. A third declines an immediate win for the lowest-numbered non-winning move whenever both options exist, and otherwise uses the priority rule. A fourth uses the priority rule with probability ¾ and samples a uniformly random legal move otherwise. The fifth is a neural player trained to copy the priority rule on 528 boards and then frozen. For a player that assigns probabilities to moves, its reported first choice is its most probable legal move, with ties going to the lowest cell. [Archived player definitions](experiments/tictactoe_pilot/torch_replay.json)
