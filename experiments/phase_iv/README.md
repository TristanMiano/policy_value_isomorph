# Reproduce and inspect Phase IV

Tic-tac-toe is fully enumerated here. A **source block** combines one independently trained perfect-play network, its random seat opponents, and its own randomized board partitions and reconstruction initializations. The same fitted model can be deployed by taking its highest immediate score (**direct**) or the largest average utility of a complete game after each possible move (**von Neumann–Morgenstern, VNM**). See the report for the exact player definitions, scoring signs, training inputs and budgets. [Plain-language report](../../PHASE_IV.md) · [Design committed before source training](../../PHASE_IV_PROTOCOL.md)

## Read the results

- [primary.json](primary.json) has the six planned differences plus descriptive draw and loss results. Each method includes its 32 source-level mean, sample standard deviation and 95% interval. Each paired difference also gives the count in each direction, a two-sided p-value, and an interval obtained by resampling whole source blocks. Holm-adjusted p-values cover the six prespecified tests. [Intervals for recurrence across sources](recurrence.json)
- [methods.jsonl.gz](methods.jsonl.gz) gives one metric per method and source class, including its network, decoder, score target, information at selection, budget, individual block means, measured spread, reference and paired difference. A `.jsonl.gz` file is gzip-compressed text with one JSON object on each line. [Objective-by-objective rankings](rankings.json) report relative performance on common source units and separate full-information or source-assisted methods from independently deployable ones. A difference from the leader is calculated on the same source blocks. Rankings after looking at all results are descriptive.
- [diagnostics.jsonl.gz](diagnostics.jsonl.gz) covers order queries, finite sampling, starting boards, training time and size, variation between fitted networks, probability and representation bounds, changed menus and changed lotteries. [paired_games.jsonl.gz](paired_games.jsonl.gz) covers playing VNM against direct, corrections and newly lost source moves, and best responses using advance knowledge of a particular opponent. [Opponent and seat summaries](opponents.jsonl.gz) give original-player, imitation and visit-trained results against each opponent group. [Probability calibration](probability_calibration.jsonl.gz) gives the count, predicted mean and exact mean by probability band. [Exact choices and board overlaps](finite_bounds.jsonl.gz) gives full-population results per player.
- [Searchable atlas](atlas.html) contains each reachable decision board for the first original, its raw counts and four fitted predictions. [Training curves](training_curves.png) compare agreement and mean points with training error and exact-target error on withheld boards. [Payoff-error and move-gap tables](return_groups.jsonl.gz) give counts, agreement and squared error for reachable and unreachable boards, finer visit-probability groups and intervals of exact game-point advantage. [By-fit denominators](return_groups_by_fit.jsonl.gz) retain empty populations explicitly. [Figure by score gap](return_gaps.png) compares the exact return with V and Q predictions trained on points, using archived scores at their stored precision. [Planning simulation](planning.json) gives candidate budgets and simulated precision and power under three assumptions about variation.

### Reading a method or metric

`V` sees the resulting board. `Q` sees the current board and move. The raw output is a fitted normalized visit count. A `terminal` VNM rule uses the signed frequency on the last move. A `sum` rule adds the signed frequencies. A `decay` rule gives the candidate weight one and each next move 0.9 times the previous weight. X moves contribute positively and O moves negatively. `copies` continues both seats with the fitted direct rule and `source` continues with the original law. A fixed source has one possible continuation. A randomized original uses 16 sampled continuations per legal candidate for these learned-frequency rules. All evaluate the same utilities under the declared player for both seats. `oracle` refers to calculations with the complete source distribution and exhaustive continuations. `exact_ordered_board` is a resulting-board score table built from every original choice. `exact_shared_frequency` averages possibly conflicting per-parent target frequencies at the same resulting board. `exact_edge_frequency` retains the exact per-board, per-move target.

The `points` and `outcomes` networks instead fit 16 simulated game outcomes per candidate. The former predicts mean points directly. The latter fits win/draw/loss frequencies and renormalizes its bounded output before taking expected points. `supplied` evaluates the supplied win/draw/loss points. `compact` fits one draw value shared across complete plays, with a win and loss fixed at +1 and −1. `random_utility` chooses with equal probability between draw values −1 and +1, then maximizes the resulting expectation. `masked` grants the extra information of which legal moves the original ever plays. `T` followed by a positive number samples moves with probability proportional to the exponential of their score divided by that number, giving each legal move equal base weight. `T0` gives equal mass to tied best moves. `Tselected` chooses among 0, 0.05, 0.25 and 1 by smallest distance to observed validation move frequencies. In the changed-menu controls the named temperature rules retain their own sampling rule. Other score rankings are evaluated under the declared source-class rule for mapping a restricted ranking to probabilities. A fixed maximum uses the lowest eligible cell for ties. Stored candidate scores used for the additional sampling study are single-precision values. Original maximum-choice decisions from the fitting run are stored separately.

`agreement` is the probability that the reconstruction and original choose the same move, averaged equally over withheld boards. For a randomized original this compares independent draws and can be below one for two identical distributions. `tv` is the mean mass that must be reassigned to reproduce the original move probabilities, with zero meaning identical. `visit_agreement` and `visit_tv` weight boards by their exact original self-play visit probability; the denominator is `selfplay_weight`. `win`, `draw` and `loss` are external opponent-panel probabilities, and `points` is win probability minus loss probability. `seats` gives the raw triples in win, draw, loss order for the evaluated player, first as X, then O. In each seat the opponent order is uniform, priority, perfect replies, untrained networks 0–4, and original player. The last matchup is separate from the weighted panel. `against_direct` gives both seats against the same fit's direct player. `move_pairs` lists counts matching both methods, direct only, VNM only and neither, against a fixed original.

A `block_id` or `block` from 0–31 identifies an independent source. `split` 0 or 1 identifies the partition within that block; within a partition, board labels 0, 1 and 2 denote training, validation and withheld boards. `fit` 0 or 1 identifies the independent recovery weights; −1 denotes a reference shared by fits. The binary NumPy archives (`.npz`) contain named arrays. The order of decision boards, legal moves and edges follows the game graph in increasing number of played moves, then board text. Cell numbers increase left to right across rows. Use `game().names`, `game().dec`, `game().parent`, and `game().cell` from [the game module](../../src/policy_value_isomorph/phase_iv_game.py) to index the arrays. Predictions or counts indexed by a legal edge refer to the same parent board and candidate move.

For numerical summaries, `sd` is the sample standard deviation across independent source-block averages, `ci95` is an individual 95% interval and `n` counts independent blocks. `paired.p` tests zero average difference against changes in either direction, assuming independent blocks and the paired Student model. `holm_p` adjusts across the reported family. The primary family is kept separate from exploratory comparisons. Exploratory method contrasts share a family within the method table, diagnostic contrasts within each named experiment. Identical observed differences have no estimable between-block test variance; the p-value is null. Conditional counts or exact finite calculations can still be compared directly. Resampling blocks describes variation in the finite game's randomized study design.

## What each block retains

| Files inside each block | Contents |
| --- | --- |
| `source.json`, `source.pt`, `source.npz` | Source seed, teacher tie ordering, loss, passes, certification, weights, raw outputs and decisions on every board. |
| `baseline.npz`, `baseline.jsonl.gz` | Partitions, raw observed legal-edge counts, imitation-network outputs, number of source turns collected, exact-encoding and imitation comparisons. Each split's raw computations are available even for shared reference laws. |
| `menus.jsonl.gz`, `sampling.npz`, `sample_laws.jsonl.gz`, `coverage.jsonl.gz` | Each restricted-menu query and response, ordered and unresolved pairs, source-draw counts by budget, finite and infinite log-ratio errors, source/opponent turns and coverage. Common and rare divide positive-weight test boards at their median visit probability. The coverage study's Q disagreement uses its largest score. Its probability error uses normalized nonnegative fitted scores, with a uniform fallback for a zero row. |
| `visits.npz`, `visits.jsonl.gz`, `examples.jsonl.gz` | Learned frequencies, VNM utilities, actual maximum-choice decisions for every legal board, board and game results, training and validation losses, and withheld examples with predicted and observed counts at the same visit total. |
| `returns.npz`, `returns.jsonl.gz`, `return_errors.jsonl.gz`, `best_reply.jsonl.gz` | Enumerated expected points, learned return and outcome predictions, magnitude and sign of matched perturbations, score-gap strata and both-seat opponent-specific best replies. `restore_lose` gives both, exact-payoff only, learned-payoff only and neither matching the original. |
| `curves.jsonl.gz`, `training_steps.jsonl.gz`, `stability.jsonl.gz`, `bounds.jsonl.gz`, `oracles.jsonl.gz` | Fitting settings, reduced coverage, optimization steps, ordering reversals, neighboring-board gaps and full-information references. Numerical board-score entries have squared frequency units when the target is a frequency. Game-payoff fits have squared game-point units. |
| `soft.jsonl.gz`, `interventions.jsonl.gz`, `lotteries.jsonl.gz`, `intervention_cases.npz` | Temperature and mask, estimated and exact choices, utility parameters and training ties, probabilities of independent move matches, predicted and true answers to changed questions. A prediction fingerprint identifies the array of frozen responses. For the common ranking comparison each predictor uses the known fixed or ¾-randomization rule after the intervention. Temperature-specific alternatives instead retain their own deployed sampling rule on the offered moves. Edited priority interchanges the first two candidates. Lottery choices record the probability offered and which option was presented first. |

## Reproduction

To replay the Checkpoint E review from the archived fits, run `python scripts/review_checkpoint_e.py` from the repository root after installing the dependencies below. It reads legal-move predictions, exact original move probabilities, self-play visits and seat outcomes. It writes the weighted copying and game comparisons, denominators and one paired difference per original to [checkpoint_e.json](../checkpoint_e.json). [Review and selections](../../CHECKPOINT_E.md)

From the repository root, install `python -m pip install -e ".[dev,phase-iv]"`. The runs used Python 3.12.3, NumPy 2.4.2, SciPy 1.17.1, PyTorch 2.11.0 and Matplotlib 3.10.8 on CPU with one numerical thread per worker. The run stages use deterministic random streams per block and purpose. All reported evaluations use the separate opponent initialization stream. Temperature selection uses only source counts on validation boards. Data checks reconstructed the primary comparisons from paired per-fit observations and compared game enumeration against a second implementation. Untrained opponent networks use 10 inputs, two 128-unit hidden layers and 9 outputs, separately initialized from the original player. The grid for the compact draw utility includes −1 and +1 in steps of 0.25. The lottery fixture trained on 64 new win/loss gambles and tested on 128 per partition; its eight probability bands were fixed before the comparisons.

Set the environment variable `PVI_PHASE_IV_OUTPUT` to an empty directory to regenerate an independent copy of the numerical outputs. With no override, the scripts use this directory. Completed stages resume from their `.done` file. Use `--force` to regenerate a stage intentionally, and regenerate dependent stages if inputs change.

```sh
python scripts/plan_phase_iv.py
python scripts/run_phase_iv.py source
python scripts/run_phase_iv.py baseline
python scripts/run_phase_iv.py probes
python scripts/run_phase_iv.py visits
python scripts/run_phase_iv.py returns
python scripts/run_phase_iv.py diagnostics
python scripts/run_phase_iv.py utility
python scripts/phase_iv_bounds.py
python scripts/phase_iv_return_groups.py
python scripts/plot_phase_iv.py
python scripts/report_phase_iv.py
python -m pytest -q
python scripts/demo_tictactoe.py
```

For a small software check use `--workers 1 --blocks 0` on each run stage. The full report requires all 32 blocks. [Archived numerical checks](../../tests/test_phase_iv.py)
